# 국내 주식 관심종목 앱

이든크루 Flutter 과제로 만든 국내 주식 관심종목 앱입니다.
관심종목, 검색, 종목 상세 화면을 구현했고 데이터는 Naver 주식 데이터를 사용했습니다.

## 실행 방법

- Flutter 3.47.1
- Dart 3.13.1
- Windows 환경에서 `flutter analyze`, `flutter test`를 확인했습니다.
- 웹에서는 Naver API CORS 문제로 실데이터 조회가 되지 않아 모바일 실행을 권장합니다.

```bash
flutter pub get
flutter run
```

폰트는 과제에 들어 있던 Noto Sans KR을 그대로 사용했습니다.

## 구현한 기능

### 관심 화면

- 관심종목의 종목명, 종목코드, 시장, 현재가, 등락 정보 표시
- 상승, 하락, 보합 색상 구분
- 시세 새로고침
- 현재가순, 등락률순, 가나다순 정렬
- 관심종목이 없을 때 빈 화면 표시
- 시세를 불러오기 전 스켈레톤 표시

### 검색 화면

- 종목명 또는 종목코드 검색
- 검색어와 일치하는 글자 강조
- 검색 전 화면과 검색 결과가 없을 때의 화면 처리
- 별 버튼으로 관심 등록 및 해제
- 관심 등록과 해제 시 토스트 표시
- 검색 결과를 누르면 상세 화면으로 이동

### 상세 화면

- 현재가와 등락 정보 표시
- 시가, 고가, 저가, 거래량, 시가총액 표시
- 1개월, 3개월, 6개월, 1년 기간 변경
- 캔들 차트와 일별 시세 표시
- 상세 화면에서도 관심 등록 및 해제 가능

검색이나 상세 화면에서 관심 상태를 바꾸면 관심 목록과 다른 화면에도 바로 반영되도록 했습니다.

## 추가로 구현한 내용

- 검색 및 상세 화면 로딩 표시
- 일별 시세 페이지 메모리 캐시
- 같은 페이지를 다시 요청할 때 기존 데이터 사용
- Naver EUC-KR/CP949 응답 처리
- 네트워크, 파싱 오류를 구분해서 처리
- 단위 테스트와 위젯 테스트

아래 선택 기능은 구현하지 않았습니다.

- 관심목록 앱 재실행 후 저장
- 최근 검색어
- 스와이프로 관심종목 삭제
- Pull to refresh
- 차트 애니메이션

## 프로젝트 구조

- `data`: Naver API 호출, 응답 파싱, DTO, Repository 구현
- `domain`: 화면에서 사용하는 모델, Repository 인터페이스, UseCase
- `presentation`: 화면, 상태, ViewModel
- `core`: 공통 컴포넌트, 에러 처리, DI

상태관리는 `ChangeNotifier`를 사용했습니다.
화면 상태와 액션은 `freezed`로 만들었고, 의존성 주입은 `get_it`을 사용했습니다.
관심 상태는 여러 화면에서 같이 사용해야 해서 `BehaviorSubject`로 전달했습니다.

사용한 주요 패키지는 다음과 같습니다.

- `http`: Naver API 요청
- `html`: 일별 시세 HTML 파싱
- `cp949_codec`: 한글 응답 디코딩
- `freezed`: 상태와 액션 모델 생성
- `get_it`: 의존성 주입
- `rxdart`: 관심 상태 스트림

## 차트

차트 패키지는 사용하지 않고 `CustomPainter`로 캔들 차트를 그렸습니다.
고가와 저가를 기준으로 차트 높이를 계산하고, 시가와 종가를 비교해서 상승, 하락, 보합 색상을 적용했습니다.

## 직접 판단한 부분

### 토스트

토스트는 검색 화면과 상세 화면에서 동일하게 보이도록 공통으로 만들었습니다.
화면을 오래 가리지 않게 0.2초 동안 표시되도록 했고 별도의 사라지는 애니메이션은 넣지 않았습니다.
연속으로 누르면 이전 토스트를 닫고 새로운 내용을 보여줍니다.

### 로딩과 에러

시세가 아직 없을 때는 스켈레톤을 표시했습니다.
검색 중이거나 상세 데이터를 불러올 때는 로딩 표시를 넣었습니다.
검색에 실패하면 다시 검색해 달라는 문구를 보여줍니다.

종목명이나 표의 글자가 길어지는 경우에는 한 줄 말줄임표로 처리했습니다.

### 정렬

현재가순과 등락률순에서 아직 시세를 받지 못한 종목은 목록 아래쪽에 배치했습니다.
값이 같으면 종목명 순서로 정렬했습니다.

### Figma와 다른 부분

Figma에 없는 로딩, 네트워크 오류, 데이터가 없는 상태는 직접 추가했습니다.
색상과 간격은 과제에 제공된 디자인 토큰을 사용했고 새로운 토큰은 추가하지 않았습니다.

## 테스트

```bash
flutter analyze
flutter test
```

- `flutter analyze`: 오류 없음
- `flutter test`: 70개 테스트 통과

API 응답 파싱, 데이터 요청, Repository, UseCase, ViewModel, 화면 동작을 테스트했습니다.
검색에서 관심종목을 추가한 뒤 상세 화면과 관심 목록에 반영되는 흐름도 위젯 테스트로 확인했습니다.

## 작업하면서 어려웠던 점

Naver API마다 응답 형식과 한글 인코딩이 달라서 JSON과 HTML을 따로 처리했습니다.
일별 시세는 기간에 따라 여러 페이지가 필요해서 필요한 수량을 얻으면 요청을 멈추고, 이미 받은 페이지는 캐시에 저장했습니다.
